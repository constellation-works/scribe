# Architecture

The layer model that `scripts/check-dependency-direction.sh` enforces
(STD-02 R1, R6). A lower layer never imports a higher one. Adding a crate or
an edge changes this file and that script in the same commit.

## Layers

| Tier | Unit | Owns | May depend on |
|------|------|------|---------------|
| 1. Business logic | `scribe-core::entry`, `::tag`, `::session`, `::activity`, `::proposal`, `::record`, `::config`, `::capture`, `::annotation`, `::control`, `::pass`, `::ask`, `::search`, `::consistency`, `::transcript`, `::verbatim`, `::models`, `::action`, `::trigger`, `::instruction`, `::issue`, `::issue_trigger`, `::memory`, `::codex`, `::provider`, `::error` | Entries (`Entry`, `NewEntry`, `EntryId`, `TagName`, `EntryStatus`, `Cite`, `ContentFrom`) and their selection; the tag table and its alias resolution; session records, the on/off control state and the pass-due rule; consistency proposals; the metadata every record shares (`Project`, `Topic`, `Related`, `Listing`); parsing `config.toml` text; finding the `#scribe` lines of a typed prompt, the prompt hash and the model-free settling commands (form 4: `approve`/`reject`/`retire`/`forget`) (`capture`); `#scribe` as an annotation: the markers of a typed turn (`#scribe` or `#scribe/global` in a sentence or opening a line, a line-start tag as the hint), the message window and request of the one bounded model call, the verbatim check of its answer and the entry draft, and the `marks.json` record shape (`annotation`); recognising `/scribe on|off|status|link` and the switch transitions (on, off, due, final, settle, link) over the control state (`control`); session links (`SessionLink`, `LinkType`), their validation (unknown, self, cycle, second parent), the derived children and the tree order (`session`); a session's `active` flag: the persisted change, the `manual`, `age` and `removed` routes applied to a loaded record (a pinned session exempt from the automatic ones, unpinned by a manual deactivation) and the age rule from the last message (`activity`); a session pass from parsed transcript to checked record: the conversation without synthetic turns, the window after `scribed_through`, the session request, the header and segment budgets, ordered segment starts, derived message ranges and dates, sealing and verbatim-term checks and the next record (`pass`), and bounded, user-quote-checked candidate statements (`pass/candidates.rs`); the `Models` port, a trait with one typed request and answer per model use, its prompt and JSON schema, and `ModelError` (`models`); answering a question: the model-free lookups (last session, named session, next steps, a tag's period, a term, the last orchestrator task), BM25 retrieval over entries, session records and Orbit tasks with the scope rules and evidence packing, the `ask` request, and the verbatim check of every claim and conflict, over records the caller loaded and the `Models` and `Tasks` ports (`ask`); the consistency scan and the settling verbs: candidate pairs and stale entries, the batch request, the verbatim-checked judgement, the proposal drafts, re-applying an interrupted approval, and `approve`/`reject`/`retire`/`forget` over loaded proposals and entries; and the removed-feature session pairs (a session and a later record with a removal cue), their request and their verbatim-checked judgement (`consistency`); reading a Claude Code transcript's bytes into messages (`transcript`); the verbatim quote check; action entries' pickups and the stuck rule (`action`); trigger phrases, the model-free gate of a tag's capture rules (`trigger`); the instruction check that an agent's write on Daniel's word is backed by a recent typed turn (`instruction`); reading a Codex desktop rollout's typed inputs fail-closed (`codex`); the transcript and model transport identity (`provider`); the crate's typed `Error`. Validating constructors and serde shapes. No I/O. | nothing internal |
| 2. Persistence | `scribe-core::store` | The `Store` facade (candidate reservations and approval recovery in `store/candidates.rs`, direct agent writes in `store/agent.rs`, exact-or-unique-prefix id resolution in `store/ids.rs`, config-first store tags in `store/tags.rs`, action entries' pickups and the stuck count in `store/pickups.rs`, each annotation marker's outcome and the locked write of its entry in `store/marks.rs`, memory items in `store/memory.rs`, issue records and their locked writes in `store/issues.rs` over the issue file format in `store/issue_file.rs`, digest-owned project scaffolding in `store/init.rs`, isolated rebuild checkpoints in `store/rebuild.rs`, list and show entries and sessions, read control state and proposals, summarize tags, fill a cite's message id, switch and mark sessions in `control.json` under the lock, write a session record and settle its pass in one locked call (merging its links), add a session link in one locked call, change one or several sessions' `active` flag in one locked call, isolate rebuild checkpoints and compare the visible revision before replacing the record, guard sealed segments on ordinary writes, record an audit event) over its private parts: `format` (Markdown-with-frontmatter and JSON documents, format probe and upgrades), `redact` (masks configured secrets in every persisted free-text field), `audit` (the audit record shape) and `fsio` (atomic write, append, advisory lock, owner-only and link checks, directory listing; knows nothing about records). The only core module that touches the filesystem. | tier 1 |
| 3. Composition | `scribe::app`, `::models`, `::tasks`, `::popup` | `app` resolves the data directory (`--root` > `SCRIBE_ROOT` > `~/.scribe`) and Claude Code's transcripts directory (`$CLAUDE_CONFIG_DIR/projects` > `~/.claude/projects`), constructs the `Store`, supplies the clock, the host name and the redactor's secret values, and composes the model adapter and the Orbit task adapter, each with its allowlisted environment. `models` is that adapter, `ClaudeCliModels`: the `Models` port over `claude -p`, run in its own process group from a cleared environment, drained, and killed and reaped at its budget. `tasks` is `OrbitTasks`: the `Tasks` port over `orbit tool run orbit.search` and `orbit.task.show`, run through `models`' supervisor from a cleared environment holding `PATH`, `HOME`, `LANG` and the `ORBIT_*` variables. `popup` runs the `scribe tmux` popup: the shell script embedded in the binary, run with `sh -c` on the caller's terminal against the started executable and the same data directory; it is the one unsupervised child, because fzf and the pager must own the tty. These three are the only modules that spawn a process. | `scribe-core` |
| 4. Surface | `scribe::cli`, `::help`, `::commands`, `::audit_middleware`, `::output` | Root argument declarations; grouped root help, each command's name and summary taken from its declaration; one module per noun (`entry`, `proposal`, `search` for `scribe search`, `consistency` for `consistency scan`, `tag`, `question` for `question ask`, `plugin` for `plugin call`, the Orbit exec backend, which runs `ask` and the two routine commands; `session/` with `pass.rs` for `session pass`, `rebuild.rs` for the confirmed, resumable rebuild and `activity.rs` for `session deactivate|activate`; and `hook/` with one file per Claude Code hook event, `annotation.rs` for cataloging the turn's markers at Stop, `codex.rs` adapting Codex's hook events onto them, `scribe_command.rs` for `/scribe on|off|status|link`, `proposal_command.rs` for the settling verbs, plus its stdin payloads, transcript provenance check and project lookup) with its flags and handlers; the audit guard around every mutating command; rendering from payloads; the only stdout/stderr/TTY access. | tiers 1–3 |

## Module rules inside crates

Checked by grep over non-test sources:

- Every `scribe-core` module except `store/` (today `entry.rs`, `tag.rs`, `session.rs`, `activity.rs`, `proposal.rs`, `record.rs`, `config.rs`, `capture.rs`, `annotation.rs`, `control.rs`, `pass.rs`, `ask.rs`, `action.rs`, `search.rs`, `consistency.rs`, `transcript.rs`, `verbatim.rs`, `trigger.rs`, `instruction.rs`, `issue.rs`, `issue_trigger.rs`, `memory/`, `codex.rs`, `provider.rs`, `models.rs`, `error.rs`, `lib.rs`, and any module added later) imports no `std::fs`, `std::net`, `std::process`, `tempfile` or `rustix`, and no `crate::store`.
- `scribe-core/src/store/fsio.rs` imports nothing from the business modules or the rest of `store`; `store/format.rs`, `store/redact.rs` and `store/audit.rs` do no file I/O.
- `scribe-core` reads no environment variables and discovers no paths (`std::env::`, `home_dir`, `current_dir`).
- `scribe/src/app.rs`, `scribe/src/models.rs`, `scribe/src/tasks.rs` and `scribe/src/popup.rs` import no `cli`, `commands`, `audit_middleware` or `output`.
- Only `scribe/src/models.rs`, `scribe/src/tasks.rs` and `scribe/src/popup.rs` spawn a process (`std::process::Command`), outside tests; `tasks.rs` only through `models::supervise`, and `popup.rs` only the interactive `scribe tmux` popup, which owns the terminal and is not supervised (see the tmux popup decision).
- `scribe/src/output/` imports no `app`, `cli`, `commands` or `audit_middleware`.
- `scribe/src/audit_middleware.rs` imports no `cli` or `commands`: dispatch depends on it, not the reverse.
- `scribe/src/commands/` writes no file (`std::fs::write`, `create`, `rename`, `remove`, `copy`, `set_permissions`, `OpenOptions`): a hook or `session pass` reads its transcript and git config, and every write goes through the store.
- Only `scribe/src/output/` touches stdout, stderr, `IsTerminal` or the color/format variables (`scripts/check-terminal-guard.sh`).

Codex model transport lives in `crates/scribe/src/models/codex.rs`, beneath the
existing Models adapter. It reuses the process supervisor in `models.rs`; `tempfile`
(previously a test dependency) supplies private, automatically removed schema and
instruction files and an isolated working directory. No domain layer spawns processes.
