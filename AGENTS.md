# scribe — agent guide

Loaded as both `AGENTS.md` and `CLAUDE.md` (a symlink). scribe is a standalone Orbit plugin that keeps Daniel's explicitly marked preferences, catalogs the sessions he turns on, and answers agents' questions with verbatim citations ([design](docs/design/scribe/1_overview.md)). It is a Rust CLI built from the constellation Rust CLI template; the first slice replaced the template's note example with scribe's domain, its Markdown-and-frontmatter store and a read-only CLI, the second added `#scribe` capture through the `hook` commands and the Claude Code package in `plugin/claude-code/`, the third added referents (`#scribe add this to <tag>`) resolved through the `Models` port and its `claude` CLI adapter, the fourth `/scribe on|off|status` and session records (later linked to the session they were spawned from or continue, with `/scribe on --from` and `/scribe link`), the fifth `ask` (`question ask`, and `scribe.ask` through the Orbit plugin tree in `plugin/.orbit-plugin/`), and the sixth the consistency routine (`consistency scan`), the settling verbs (`#scribe approve|reject|retire|forget`), the `SessionStart` hook and the two routines, seeded disabled; store format 4 (S8) made a session record a header over a log of segments (`session show --log`, `--segment`, `session:<id>#<n>`), added the `active` flag (`session list --include-inactive`) and recorded authors on entries and proposals; S9 made passes write bounded segments with enforced sealing and added checkpointed `session rebuild`; S10 added its routes: `session deactivate|activate` by hand, and the consistency scan's `age` (`[sessions] inactive_after_days`) and `removed` deactivations; S11 added the model-free read surface: `scribe search`, list filters (`--since`, `--until`, `--status`, repeated `--topic` and `--related`, authors, proposal states) and unique id prefixes for every command taking an id; S12 adds audited agent entry, tag and proposal writes, config-first store tags and deterministic agent attribution in `ask` (store format 5); action tags (`standard`, `remind`, `idea`, or any tag config marks `action = true`) keep a capped transcript window on `#scribe` capture, take agent entries with a cancel window and a quote check, are left out of `ask` unless asked for, and are read with `entry list --after --window` and noted with `entry pickup` (store format 8, `pickups.json`); the tmux popup is the read-only `scribe tmux` subcommand (`commands/tmux.rs`, running the fzf script `popup.sh` embedded by `popup.rs`); `finding` entries (store format 10) record an agent's measured or verified result with an evidence pointer and an as-of date — no evidence or a fourth finding in one session is refused — and read back only through `ask` and `scribe search` as that agent's claim, while the session pass also proposes candidates from assistant turns (a finding, or a check-back or idea under the shipped `remind` or `idea` action tags) whose typed approval writes one agent-authored entry. Store format 11 adds per-tag capture rules (`[tags.<tag>.capture]`, read with `scribe tag show <tag>`): the pass asks only for claims from Daniel's turns that fire a tag's trigger (`trigger.rs`), checks each again under the lock, and records `admitted: {trigger, matched, criteria}` on the candidate; so it no longer opens candidates from assistant turns, though stored ones still approve. The instruction check (`instruction.rs`, `commands/instruction.rs`) backs a write an agent runs on Daniel's word: `proposal settle` and `entry retire` take `--session` and `--instruction` together, and refuse `instruction_not_found`, `instruction_stale`, `instruction_mismatch` or `not_interactive` before the lock; a passing check lets `entry retire` accept Daniel's entry (keeping its text), `entry forget` (only with an instruction and `--confirm`) blank an entry's text and the proposal quotes of it for good, and `proposal settle` approve or reject a session-pass candidate (never a proposal about his entry): an approval writes the reserved entry as a typed approval would, with `approved_by` the agent and the instruction recorded, a rejection closes it `instructed`; their audit lines carry the instruction's session and message ids (audit format 3). Store format 12 adds an entry's `inactive_since` (when it left `active`, never moved by metadata writes), which Stop recovery's turn-time coverage read in whole seconds until §14 step 2 removed recovery. Store format 14 gives every pass claim a `statement` (≤300 characters) and `subject` (≤80; empty opens nothing) beside its quote; approving one writes the statement as content, the quote in `quote` and `stated_by: {kind: scribe, name: session-pass}`, and `ask` attributes a claim to Daniel only when its quote lies in that `quote`. Store format 15 admits an instructed approval's `said` (the `scribe proposal settle` command run) and `closed_reason: covered` for an approved claim whose missing entry an active one now covers, which keeps its settlement and instruction. Store format 16 adds an entry's `outcome` (`open`, `parked` with Daniel's words, or `task`): under a tag whose capture route is `write` (the shipped `idea`) the pass writes a checked claim from Daniel's turn itself as an entry authored by `scribe:session-pass`, with no proposal, at most 3 per session per run (`MAX_IDEAS`), after the shared duplicate checks and with existing ideas sent to the model as exclusions (`write_exclusions`); an idea that became a task in the session writes nothing, and readers label these entries as captured by the pass. Store format 17 adds issue records (`issue.rs`, `store/issues.rs`, `store/issue_file.rs`, `commands/issue.rs`): `scribe issue add|occur|update|move|search|show|list` write and read `issues/issue-<n>.md`, the memory of an incident across projects and what fixed it; an agent writes one in the session Daniel asked in, with his request checked verbatim (`--request`, `quote_required`, `quote_not_found`), its error lines labelled as agent evidence, and no approval; an occurrence on a resolved issue reopens it (`recurred: true`); `issue` is a reserved tag; `scribe search --kind issue` and `ask` return issues as the agent's account with his quoted request; `#scribe forget <issue-id>[#<n>]` (`hook/issue_command.rs`) blanks an issue or removes an occurrence; and each issue write or forget audits its ids under `issue` (audit format 4). Store format 18 adds an entry's `removal_instruction` (the instruction it was retired or forgotten on), so `instruction` is only ever the one `approved_by` approved on; an instructed settlement is refused when the instruction predates the claim's `opened_at` or its turn has no message id. Store format 19 adds memory (`memory.rs`, `store/memory.rs`, `commands/memory.rs`): in a switched-on session the pass also returns up to three memory elements per pass, each checked (verbatim quote of Daniel's own turn, section switch, redactor, finance and sensitive words, mood rule) and written under the lock as `memory/m-<n>.md` items with newest-first occurrences; `scribe memory show|ack|retire|forget` read and correct them, and the `SessionStart` hook gives an interactive session (`CLAUDE_CODE_ENTRYPOINT=cli`) the memory page as `additionalContext`. The prompt hook matches the `issue` triggers (`[tags.issue.capture]`, else the shipped route-`agent` rules `TagTable::issue_capture` returns) in Daniel's own words of every typed turn, on or off, and on a fire adds one root-cause line to the agent's `additionalContext` and one audit line (verb `fire`, session, trigger, prompt sha256; audit format 5, which also gives `issue add|occur` lines the request turn's hashes); `scribe issue stats [--since]` (`Store::issue_stats` over `store/audit.rs`) counts fires, writes and withdrawals from the log, with precision and trigger-yield proxies. Store format 20 adds memory consolidation and promotion (`memory/consolidate.rs`, `memory/promote.rs`): the pass promotes a `now` item to `milestones` on the `[memory.promote]` rules (a profile change, which also writes the new profile item and supersedes the old one; recurrence in `recurs_in_sessions` sessions; a `user_says` phrase in the turn), moving its occurrences onto the milestone with a `promotion` journal; the consistency scan's memory steps (after the entry steps, before the session steps) label overlapping active items `same`, `contradicts` or `unrelated` with verbatim quotes, merge (`merged_into`), supersede (`superseded_by`) or remember the pair (`unrelated_to`), complete journalled promotions and recount recurrence, reporting a `memory` block; `scribe memory rules` prints the effective rules with their origin. Store format 21 adds a `working` item's `preference_proposal`: when a draft brings a `working` item to `[memory] promote_working_sessions` distinct sessions, the pass opens one `preferences` candidate under the lock (`Store::open_memory_candidates`, admitted `memory:recurs`, within the 20-open cap and the shared duplicate checks) and records it on the item, so it opens once; approval stays Daniel's. Store format 22 adds annotations (2_design.md §14, step 1): a `#scribe` marker inside a sentence of a typed turn (`annotation.rs`) is echoed by the prompt hook and cataloged by the same turn's Stop (`hook/annotation.rs`) with one bounded `models.annotation` call per marked turn; the checked answer is written as Daniel's entry with scribe's statement as content, his verbatim span in `quote` and `stated_by: {kind: scribe, name: annotation}`, and each marker's outcome (entry, none, refused with its code, pending) goes to `marks.json` (`store/marks.rs`), ids and codes only. Under `--provider codex` (ORB-26535) the Codex adapter (`hook/codex.rs`) echoes a marker once the typed turn is verified in the rollout, and Stop catalogs it from the Codex rollout, with the same bounds and outcomes. Step 2 (§14.6, ORB-26530, no format change) folds forms 1–3 into the marker: every `#scribe` line but a whole-line settling command is a marker, its tag (`#scribe idea: …`, or `… to preferences` at the line's end) a hint the model must follow, under Claude Code and Codex alike; `capture.rs` parses form 4 only, and the referent call, `Store::capture` and Stop recovery are gone, while a marker on a line an older verbatim entry cites is not cataloged again; `models.referent` still loads, logging that it is unused.

## Rules

- Work only on authorized scope. Neither implementation nor a PR request authorizes merging.
- Don't add a crate, or a dependency between crates, without updating [`ARCHITECTURE.md`](ARCHITECTURE.md) and `scripts/check-dependency-direction.sh` in the same change.
- Update affected docs in the same PR as the code. Stale docs are a review blocker.
- Don't touch `CHANGELOG.md` during tasks; it is compiled at release time.
- Every test must exercise behavior. No text-matching tests (`include_str!` plus `contains()` over source or copy).
- A fix comes with a regression test through the real entry point (the built binary or the public API), seen failing before the fix.
- Tests never touch real host state: temp roots, and `HOME`/`SCRIBE_*` set on the child command ([`tests/support`](crates/scribe/tests/support/mod.rs)).

## Branching

- `agent-main` — integration branch; commit directly (gate `direct`). `main` — releases only.

## Gates

`make ci-fast` (fmt, structure, `standards-check`), `make ci-lint` and `make goldens` must pass before a task moves to review. After an intended change to help or output, run `make goldens UPDATE=1` and review the diff as a contract change. `make ci` (everything, including tests and doctests) runs in CI on Linux and macOS.

## Code

- Layers: [`ARCHITECTURE.md`](ARCHITECTURE.md). Design and decisions: [`docs/design/scribe/`](docs/design/scribe/); new features copy [`docs/design/_templates/`](docs/design/_templates/).
- `scribe-core` is the domain: no clap, no terminal, no environment reads. Business logic (`entry.rs`, `tag.rs`, `session.rs`, `activity.rs`, `proposal.rs`, `record.rs`, `config.rs`, `capture.rs`, `control.rs`, `pass.rs`, `ask.rs`, `action.rs`, `search.rs`, `consistency.rs`, `transcript.rs`, `verbatim.rs`, `trigger.rs`, `instruction.rs`, `issue.rs`, `issue_trigger.rs`, `models.rs`, the `Models` port) does no I/O; everything that touches disk is in `store/`, and persisted free text passes `store/redact.rs`. The CLI crate parses (`cli.rs`), composes (`app.rs`), reaches models and Orbit tasks through the two process-spawning adapters (`models.rs`, `ClaudeCliModels`; `tasks.rs`, `OrbitTasks`, which reuses the model adapter's supervisor), dispatches (`commands/`, one module per noun holding its flags and handlers; a large noun becomes `commands/<noun>/` with one file per verb), audits (`audit_middleware.rs`) and renders (`output/`).
- Every mutating command is audited: declare it in `Command::audit` (the match is exhaustive, so a new command must decide). Read-only commands return `None`; they never write. A hook writes one line per write, refusal or `issue` trigger fire, and none when it changed nothing. Audit lines carry ids and error codes, never argument values or messages.
- Lints come from `[workspace.lints]`: no `unwrap`/`expect` in production code, no `print!` (use `tracing`), no lock guard across `.await`, no wildcard arm on an enum, no narrowing `as`. CI runs clippy with `-D warnings`.
- Only `crates/scribe/src/output/` touches stdout, stderr, TTY state or color/format env vars. stdout is payload only.
- Errors: typed `thiserror` enums; the core's `Error` crosses into `CliError` through its one `#[from]`. Exit codes: 0 ok, 1 failure, 2 usage.
- `--json` field names, the list envelope (`entries`, `sessions`, `proposals`, `tags` or `items`, with `total`, `truncated` and `warnings`) and the store's persisted shape are contracts: add fields, never rename or retype them. A persisted-shape change bumps the store format and appends a step to `store/format.rs::UPGRADES`.
- Default to `pub(crate)`; workspace dependencies via `.workspace = true`.
- Unit tests live in a sibling `tests/` directory mirroring source file names, declared in its `mod.rs`; crate-root `tests/` is integration only.
- Never put internal task, friction or record ids in help, examples or messages; use placeholders such as `<id>`.
- Store writes go through `store::fsio::write_atomic` (the audit log through `append_private`) under the store lock. Never rewrite a durable file in place. Reads never write or lock. Store state is owner-only and checked on every load.
- Report commands and outcomes at handoff — passed, failed, not run — never "tested".
