# Scribe's Codex-enabled Orbit package

This generated variant of `plugin/.orbit-plugin` adds the narrow startup writes
needed by the Codex CLI. It has the same `scribe` identity, tools and disabled
routine defaults. It replaces the default Orbit package rather than installing a
second Scribe plugin. Both Claude and Codex sessions can then use the same store.
The separate native Codex package is `plugin/codex`.

Use an Orbit build supporting `spec.permissions.fs.write_files`; older builds
refuse the manifest. Authenticate the Codex CLI normally first. The existing
`installation_id` file must be a user-owned regular file with one hard link,
without symlink components or group/other write access. Scribe copies no auth
and never creates or changes the permissions of provider files for setup.

First register this variant **without grants** in the intended Orbit workspace.
For an existing Scribe install, the widened upgrade disables the plugin and
clears its grants while preserving configuration and routines. Its new settings
then become available through `orbit config set`. Use the actual provider state
directory; do not point runtime writes at its parent, auth file or configuration:

```sh
orbit plugin upgrade scribe plugin/orbit-codex/.orbit-plugin
orbit config set plugins.scribe.codex_home /home/<user>/.codex
orbit config set plugins.scribe.codex_runtime_tmp /home/<user>/.codex/tmp
orbit config set plugins.scribe.codex_installation_id /home/<user>/.codex/installation_id
orbit plugin validate plugin/orbit-codex/.orbit-plugin --render
orbit plugin enable scribe --grant fs,network,env_pass,orbit_tools
```

On a fresh setup use `orbit plugin add plugin/orbit-codex/.orbit-plugin` without
`--enable`, configure these paths plus the store root and Claude transcripts,
then validate and enable as above. The default package's settings API does not
declare the two new runtime keys, so configure them only after registration.
Inspect and accept the rendered filesystem grants:
Codex's state root is read-only except for its `tmp` subtree and the exact
`installation_id` file. Its auth, configuration and transcripts receive no write
grant. No unsandboxed permission is requested. `codex` and `claude` must both be
reachable from the scheduler's execution environment.

Existing routine enablement, pause state and schedules are preserved during an
upgrade. This package does not enable a scheduler or turn recording on. The
human's `/scribe on` and trusted native hooks still control recording; opted-in
Codex sessions use Luna by default. Ask remains the only agent-callable MCP tool.

Run `python3 scripts/sync-orbit-packages.py` after changing the canonical Orbit
package; `make ci-fast` checks generated bytes and executable modes. For isolated
conformance, use an Orbit version with `plugin test --fixture-config`, an empty
temporary HOME/Orbit workspace, and an explicit fixture JSON containing the
three required Codex paths. Create an empty temporary `installation_id` and
temporary `tmp` directory first. Leave `root` at its unset default to exercise
the eight refusal cases without invoking a model. Never supply production
provider/store paths to conformance tests.
